# 法人データ収集ツール

企業名リスト（CSV）を入力として受け取り、各社の公式HPから「郵便番号・住所・代表者名」を自動収集してCSVに出力するPythonスクレイピングツールです。

---

## ファイル構成

```
a4-company-scraper/
├── scraper.py          # HP推定・会社概要ページ取得
├── extractor.py        # 郵便番号・住所・代表者名の抽出ロジック
├── runner.py           # メイン実行スクリプト（CSV入出力・進捗管理）
├── requirements.txt
├── demo.html           # デモUI（ブラウザで開くだけで動く）
├── results/            # 出力ファイル置き場（gitignore推奨）

│   ├── manual_check.csv# 要確認・失敗分
│   ├── progress.json   # 再開用進捗
│   └── run.log         # 実行ログ
└── tests/
    ├── test_extractor.py
    └── sample_html/    # ダミーHTMLパターン（実サイト不使用）
```

## 使い方

### 基本実行

```bash
python runner.py --input companies.csv --col 企業名
```

| オプション | 説明 |
|-----------|------|
| `--input` / `-i` | 入力CSVファイルパス（必須） |
| `--col` / `-c` | 企業名の列名またはインデックス（デフォルト: `企業名`） |
| `--limit` / `-n` | 処理上限件数（テスト用。省略で全件） |
| `--resume` / `-r` | 前回の続きから再開 |
| `--dry-run` | HTTPアクセスなしで処理フロー確認 |

### 再開（途中再実行）

```bash
# 中断後も --resume で続きから処理
python runner.py --input companies.csv --col 企業名 --resume
```

### デモUI

`demo.html` をブラウザで開くだけで、ダミーデータを使った動作確認ができます。
外部へのアクセスは一切行いません。

### テスト実行

```bash
pytest tests/ -v
# 39テスト、すべてダミーHTML（tests/sample_html/）に対して実行
```

## 抽出の仕組み

### 3ステップの処理フロー

```
企業名
  ↓
[1] HP特定 (scraper.py)
    DuckDuckGo で「企業名 会社概要」を検索
    → .co.jp / .jp ドメインを優先して公式HP URL を推定

  ↓
[2] 概要ページ遷移 (scraper.py)
    トップページのリンクを解析
    「会社概要」「company」「about」等のページへ自動遷移

  ↓
[3] データ抽出 (extractor.py)
    ┌ 郵便番号: 〒付き優先 → 〒なし（文脈限定）
    ├ 住所:     都道府県起点パターン + 住所ラベル近傍優先
    └ 代表者名: th/td → dl/dt/dd → 平文テキスト の順に検索
               「代表取締役」「CEO」「代表者」等14種ラベル対応

  ↓
スコアリング
    全3項目 → "完全"
    1〜2項目 → "要確認"（人手確認リストに分離）
    0項目   → "取得失敗"
```

### 対応HTMLパターン

| パターン | 例 |
|---------|---|
| `<table>` th/td 形式 | 最もよくある会社概要テーブル |
| `<dl>` dt/dd 形式 | 定義リスト形式 |
| `<p>` / `<span>` 平文 | ラベル+テキストの混在形式 |
| 英日混在 (CEO 等) | 英語役職ラベルにも対応 |

## 精度の考え方：自動＋人手のハイブリッド

自動スクレイピングは「8割を素早く取る」ことに特化し、残りを人手で補います。

```
自動収集 (本ツール)
  → スコア "完全":  そのまま採用（想定70〜80%）
  → スコア "要確認": 人手で確認（想定15〜20%）
  → スコア "取得失敗": 手動検索（想定5〜15%）
```

スコアに応じてファイルを分離出力するため、人手確認の優先順位付けが容易です。

## 法令・規約遵守（最重要）

本ツールは以下を厳守して設計されています。

### robots.txt の尊重

```python
# scraper.py 抜粋
def can_fetch(url: str) -> bool:
    rp = _get_robots(base_url)
    return rp.can_fetch(USER_AGENT, url)
```

アクセス前に毎回 robots.txt を確認し、`Disallow` されているパスはスキップします。

### アクセス間隔

```python
SLEEP_MIN = 3.0  # 秒
SLEEP_MAX = 5.0  # 秒
# アクセス前にランダムスリープを入れる
wait = random.uniform(SLEEP_MIN, SLEEP_MAX)
time.sleep(wait)
```

同一サーバーへの連続アクセスを避け、過負荷をかけません。

### User-Agent の明示

```
Mozilla/5.0 (compatible; CompanyDataCollector/1.0; +https://github.com/your-repo; polite-bot)
```

ボットであることを明示し、連絡先URLを含めます。

### 取得対象

- 各社が公開している **公式HP上の情報のみ** を取得します
- ログインが必要なページ・非公開情報は取得しません
- 個人情報（非公表の個人の住所・連絡先等）は対象外です

### その他

- リトライは最大2回（指数バックオフ）
- タイムアウト 10秒（長時間接続を防止）
- テスト・動作確認はローカルのダミーHTMLのみ使用（実在サイトへの大量アクセスなし）

## 処理時間・採算メモ

### 処理速度の試算

| 項目 | 数値 |
|------|------|
| 1社あたりの処理時間 | 約15〜25秒（検索1回+概要ページ取得1〜2回+スリープ込み） |
| 1,120件の総処理時間 | 約5〜8時間（自動・無人実行） |
| 手作業との比較 | 手作業 1件3〜5分 × 1,120件 = 56〜93時間 → **自動化で1/10以下** |

### 収益試算（報酬3円/件）

| シナリオ | 完全取得率 | 完全件数 | 報酬試算 |
|---------|-----------|---------|---------|
| 楽観    | 80%       | 896件   | 2,688円 |
| 中央値  | 70%       | 784件   | 2,352円 |
| 保守    | 60%       | 672件   | 2,016円 |

要確認分を人手補完すれば完全取得率を85〜90%に引き上げ可能。
ツール実行（自動）＋要確認分の人手確認（数時間）で対応できます。

## 制限事項・注意点

- HPが存在しない・ドメインが一般的でない企業は取得失敗になる可能性があります
- 会社概要をPDFで提供しているサイトはHTMLスクレイピングの対象外です
- JavaScriptで動的に情報を表示しているSPAサイトは取得精度が下がります（対策: Selenium追加は拡張可能）
- 同一グループ企業で同じドメインを共有するケースは、ページ特定精度が下がる可能性があります
- DuckDuckGoの検索結果は変動するため、まれに誤ったHPを取得することがあります（要確認フラグで対応）
